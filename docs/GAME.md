# Логика игры

## Обзор

Многопользовательская шахматная игра работает через WebSocket. Архитектура разделяет **состояние игры в памяти** и **постоянное хранение в MongoDB**.

### Принципы

- При поиске оппонента в MongoDB создаётся **минимальная запись** (ID участников, имена, настройки)
- Основное состояние игры (позиция, ходы, таймер) хранится **в памяти сервера** через WebSocket
- В MongoDB игра сохраняется **только** при завершении или отключении игрока
- При переподключении игрок получает текущую позицию из памяти и продолжает игру

---

## Этап 1: Подключение и поиск текущей игры

Когда клиент подключается к WebSocket и отправляет событие `startApp`, он указывает `color` (`"wite"` или `"black"`) — за какую сторону хочет играть. Сервер ищет незавершённую игру (`result: "pending"`), в которой текущий пользователь является участником.

**Логика поиска** (`src/controllers/game.js` → `findCurentGame`):

- Если клиент указал `color: "wite"` — ищет игру, где `ownerWite = userId`
- Если клиент указал `color: "black"` — ищет игру, где `ownerBlack = userId`
- Если `color` не указан (переподключение с другого устройства) — ищет игру, где пользователь является участником за **любую** сторону (`ownerWite` или `ownerBlack`)
- Если игра найдена — возвращает позицию, имена игроков, рейтинги и информацию о ходе
- Если нет — возвращает пустой ответ (клиент начинает новый поиск оппонента)

> **Примечание:** сервер не хранит информацию о том, за какую сторону играет пользователь между сессиями. Цвет определяется клиентом при каждом подключении. При переподключении с другого устройства (когда цвет неизвестен) сервер ищет активную игру за обе стороны.

## Этап 2: Создание или поиск игры

Клиент отправляет событие `startGame` с параметрами:

| Параметр      | Описание                                         |
| ------------- | ------------------------------------------------ |
| `color`       | `"wite"` или `"black"` — за какую сторону играет |
| `typeGame`    | Тип игры (standart, fisher)                      |
| `timeControl` | Контроль времени в секундах                      |
| `timePluse`   | Добавление времени за ход                        |

### Логика создания (`createSearchRoom`)

1. Сервер ищет существующую открытую игру (`statusGame: "open"`, `result: "pending"`) с совпадающими параметрами (`typeGame`, `timeControl`, `timePluse`)
2. Если найдена — второй игрок назначается как `ownerBlack`, существующая игра возвращается клиенту (новая запись не создаётся)
3. Если не найдена — создаётся новая игра в MongoDB
   - Текущий пользователь назначается на сторону белых (`ownerWite`)
   - Игра получает статус `"open"` (ожидание оппонента)
   - Возвращается `game._id` — ID созданной игры

> **Механика мэтчинга:** если два игрока нажали «Новая игра» с одинаковыми настройками (тип, тайм-контроль, добавление), второй игрок подключается к существующей открытой игре вместо создания дубликата. Это предотвращает ситуацию, когда два игрока ищут друг друга, но создают две отдельные комнаты.

## Этап 3: Игровой процесс (в памяти)

После того как оба игрока подключились, игра ведётся **полностью в памяти сервера**. Позиция, ходы и состояние таймера не записываются в MongoDB до завершения игры.

### Состояние игры в памяти

Каждая активная игра хранится в объекте в памяти сервера:

```
gameId → {
  position: [...],       // текущая позиция на доске
  move: true,            // чей ход (true = белые)
  players: {
    wite: { ws, userId, name, rating },
    black: { ws, userId, name, rating }
  },
  gameData: { ... }      // ссылка на запись в MongoDB (для сохранения при необходимости)
}
```

### Обмен ходами

Клиент отправляет событие `game` с текущей позицией:

```json
{
  "event": "game",
  "token": "<JWT_TOKEN>",
  "position": ["rnbqkbnrpppppppp88888888888888888888888888888888PPPPPPPPRNBQKBNR"],
  "move": "e2e4"
}
```

Сервер:
1. Обновляет позицию в памяти
2. Переключает ход
3. Отправляет обновлённую позицию **обоим** игрокам

### Рассылка ходов

При получении события `startGame` или `game` сервер отправляет обновление не только отправителю, но и оппоненту (если тот подключён):

```js
if (opponentId && clients[opponentId]) {
  clients[opponentId].send(JSON.stringify(res));
}
```

## Сохранение в MongoDB

### При завершении игры

Когда один из игроков отправляет результат (победа, ничья), сервер:
1. Обновляет запись в MongoDB: `result`, финальная `position`, `dateGameOver`
2. Уведомляет обоих игроков

### При отключении игрока

Когда WebSocket-соединение закрывается (`close` event):
1. Сервер определяет, к какой игре относится отключившийся игрок
2. Сохраняет текущее состояние в MongoDB (текущая позиция, статус)
3. Если оппонент всё ещё подключён — уведомляет его об отключении соперника
4. При переподключении игрок получает текущую позицию из памяти и продолжает игру

### Переподключение

1. Клиент подключается к WebSocket и отправляет `startApp` (с `color` или без)
2. Сервер ищет активную игру в памяти по ID пользователя
3. Если игра найдена — возвращает текущую позицию и состояние
4. Клиент продолжает игру с того же места

## Структура игровой сессии в MongoDB

Игра хранится в `game_db`, коллекция `game`:

| Поле | Значение |
|------|----------|
| `statusGame` | `"open"` — ожидание оппонента, `"close"` — игра идёт |
| `position` | Массив строк доски (FEN-подобный формат). При создании — пустой массив, при завершении — финальная позиция |
| `result` | `"pending"` — игра не завершена, `"1-0"` — белые выиграли, `"0-1"` — чёрные, `"0.5-0.5"` — ничья |
| `ownerWite` / `ownerBlack` | Ссылки на пользователей (MongoDB ObjectId) |
| `nameWite` / `nameBlack` | Имена игроков |
| `reitingWite` / `reitingBlack` | Рейтинги игроков |
| `dateGameOver` | Дата завершения игры |

> **Важно:** поле `position` при создании игры пустое или содержит начальную позицию. Обновляется только при завершении или отключении. Текущая позиция во время игры хранится в памяти сервера.

## Состояние на клиенте

Клиент хранит текущее состояние игры и обновляет его при получении сообщений от сервера. Основные данные:

- Текущая позиция на доске
- Кто ходит (`move: true` — ход белых, `false` — ход чёрных)
- Имена и рейтинги игроков
- ID игры (для отслеживания)
- ID оппонента (для отправки обновлений)
- Статус подключения оппонента
